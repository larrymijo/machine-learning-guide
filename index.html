What machine learning is

Lecture 1 · Géron ch. 1
Lecture definition
A collection of methods that let computers learn patterns from data, and use them to make predictions or decisions.

The contrast that carries the whole definition: instead of a programmer writing every rule by hand, the rules are learned from examples. Exam

Mitchell's definition, word for word. A program learns from experience E with respect to task T and performance measure P, if its performance at T, measured by P, improves with E. Add the qualification the lecture makes: P must match what good means for the application — a recommender optimised for clicks is not one optimised for people finishing the show.

AI, ML, deep learning — and where data science sits

Nesting one of these is not a subset

Data science is not a subset of AI. It overlaps where it uses machine learning, but it also covers descriptive statistics, dashboards and data cleaning, none of which is AI. That is the trap in this question.

Why learning beats rule-writing

It is tempting to read machine learning as "rules, but automatic". The real difference is generalisation. A hand-written rule covers the cases its author thought of; a learned model is fitted to a pattern, so it also handles cases nobody enumerated — a spam email with new wording, a flat slightly larger than any in the training data.

That is also the whole source of the field's difficulty. Because the model generalises from examples, it can generalise wrongly: it can latch onto an accident of the training sample (overfitting), inherit a bias that was in the data, or fail silently when the world changes and the old pattern stops holding. Everything else in this course — splitting the data, measuring on unseen rows, cross-validation, regularisation — exists to detect and limit those failures. A rule-based system is rigid but auditable; a learned model is flexible and must be tested.

When not to use machine learning

If the rule is known, exact and stable — VAT at 25%, a leap-year test, a sorting order — write the rule. Machine learning earns its place when the pattern is real but too complex or too fluid to write down, and you have enough labelled examples of it.

The classes of learning algorithm

Lecture 1 · sorted by learning signal
TypeWhat the data looks likeTypical output
Supervisedevery sample carries a labelclassification or regression
Unsupervisedno labels at allclusters, components, anomalies
Semi-superviseda few labelled, many notlabels propagated to the rest
Reinforcementno labels — rewards from an environmenta policy: what to do in each state

Semi-supervised matters when examples are cheap but expert labelling is expensive — medical images are the standard case. Reinforcement learning has an agent acting in an environment, receiving a new state and a reward, and learning a policy that maximises total reward. Self-supervised learning generates its own labels from the data, for instance by hiding a word and predicting it.

Classification or regression? both supervised — the target type decides

Classification asks which class and predicts a category. Regression asks how much and predicts a number on a continuous scale.

Three kinds of classification

  • Binary — exactly 2 classes. Spam / not spam.
  • Multiclass — more than 2, one answer each. Cat / dog / horse.
  • Multilabel — several labels at once. A photo with a cat and a dog.

Three kinds of regression

  • Simple linear — one feature, a straight line.
  • Multiple linear — several features, one target.
  • Polynomial — a curved relationship.
The test that separates them

Multiclass or multilabel? Ask whether two answers can be true at the same time. If they can, it is multilabel. The number of possible classes does not decide it.

Simple, multiple or polynomial? Count the inputs first, then ask whether the relationship bends. Rainfall and crop yield bends — too little rain lowers yield, and so does too much.

How to tell them apart in one question

Every "which kind of learning / which task is this?" question on the paper falls out of two tests, applied in order.

First: is there a label column? Labels for every row → supervised. None at all → unsupervised. A few labelled rows among many unlabelled → semi-supervised. No dataset, but a reward for acting → reinforcement.

Then, if supervised: what type is the label? A continuous number → regression. One of a fixed set of categories → classification, whether there are two categories or twenty.

Notice what the test never depends on: how the data looks, how many features there are, or which algorithm you intend to use. It depends only on the output. "Predicting the number of website visitors" sounds like counting, but the output is a continuous quantity, so it is regression; "which of ten digits is this?" has a numeric-looking output, but the ten digits are categories, so it is classification.

Training and inference

Every supervised model has two stages. Training learns the parameters from labelled data; then they are frozen. Inference applies that frozen model to new data. Training is slow and happens once; inference is fast and happens many times.

The exception

k-NN does no real training. It stores the training data and does all the work at prediction time. That is what instance-based learning means, and it is why k-NN gets slow on large datasets.

The pipeline, drawable from memory

Collect → preprocess (clean and transform) → split → choose an algorithm → train → test once on unseen data.

Exam · the five-step version to memorise

Part E asks you to put the workflow in order, and the paper's own list has five steps:

1. Define the prediction problem → 2. Prepare and clean the data → 3. Train using the training data → 4. Select or tune the model using the validation data → 5. Evaluate the final model on the test data.

Two constraints fix that order and are worth saying out loud if asked to justify it. Cleaning must precede training, because no model learns from a column that is half text and half numbers. And the test evaluation is last and happens once — the moment you tune against it, it stops being an estimate of performance on unseen data.

Data quality: the five problems

Part D of the exam · identify the flaw and name it

Before a model can learn anything the data has to be correct, not merely present. The exam hands you a small table and asks you to find the problems and classify each one — and the classification is where the marks are. "Row A04 looks wrong" earns nothing; "row A04 has a wrong data type: the word forty sits in a numeric column, so pandas reads the whole column as text and no arithmetic works until it is converted" earns full marks.

There are five recurring problems, plus one column type that is not a flaw but still has to go. Learn the five names; they are a free checklist you can run over any table you are shown.

ProblemHow it shows upWhat to do about it
Missing value blank cell, NaN, None, the word "missing", ?, or a sentinel such as -999 drop the row, drop the column, or impute with the mean, median or mode — and justify which, based on how much is missing and whether the column matters
Duplicate record the same observation appears twice, identical in every column drop exact duplicates; the copy doubles that row's influence on training and can land on both sides of a train/test split
Wrong data type a word in a numeric column (forty), a number stored as text ("1 299 kr"), a date stored as a string convert the column, after checking what the entry was meant to say; one bad cell turns the entire column into text

Exam · how to write the answer to Part D

One line per problem, in three pieces: where it is · what kind of problem it is · what you would do. For example: "Delivery Time for A02 is missing; with only six rows I would impute the median rather than lose a sixth of the data, and I would check whether the delivery simply never happened — the Delivered column says no, so the blank may be meaningful rather than an error."

That last clause is worth noticing. Missingness can itself be information. A blank delivery time for an undelivered order is not a recording failure; filling it with the median would invent a delivery that never occurred.

Why an ID column is dangerous, not just useless

Customer ID has no real relationship with anything you want to predict. The problem is that a flexible model does not know that. Given a unique number per row, a deep decision tree can build one branch per customer and reach 100% training accuracy while learning nothing that transfers to a new customer. The training score looks superb and the test score collapses. Drop identifiers before training — or extract the part that carries real information (a date, a branch code, a product category) and drop the rest.

Missing data and outliers

Lecture 2 · plus the two outlier notebooks

Garbage in, garbage out. Dirty data — missing values, impossible values, wrong labels, inconsistent units, duplicates — cannot be fully repaired even by a strong algorithm. Wrong labels make the model learn the wrong relationship; missing data makes patterns invisible; inconsistent formats split one meaning across several categories.

1 · Remove

  • Drop the row, or the column if mostly empty
  • Fine when few rows are affected
  • Risk: you lose information

2 · Impute

  • Mean — numbers without outliers
  • Median — numbers with an outlier
  • Mode — categories and text

3 · Fill from a neighbour

  • Forward fill takes the previous value
  • Backward fill takes the next
  • Only when the data is in time order
Leakage

Learn the fill value on the training set only, then apply that same learned value to validation and test. Computing a median across the whole dataset leaks the test set into your preprocessing before you have even trained anything.

Detecting outliers — two methods, and when each fails

Detection is not deletion. An unusual value may be a typo or a broken sensor, but it may also be a genuinely rare and genuinely real observation. Drag the red point and watch which method notices.

Masking — the notebook's point

Outliers inflate the mean and the standard deviation, so one extreme value can hide another. Adding 130 alone gives it z = 6.141 — flagged. Add 1000 as well and σ jumps from 4.886 to 63.511, so 130's z falls to 0.402 and it is no longer flagged. Quartiles barely move under the same treatment. That is the one-line answer to "when would you prefer IQR?"

z = (value − mean) ÷ standard deviation flag when |z| > 3 Best when the data is roughly bell-shaped. With few points, one extreme value inflates σ and hides itself.
IQR = Q3 − Q1 flag below Q1 − 1.5×IQR  or  above Q3 + 1.5×IQR Needs no normality. Values exactly on a fence are not flagged, and 1.5 is a convention, not a law.
A boxplot's whiskers are not its fences

With whis=1.5 each whisker reaches the most extreme observed value still inside the fence, not the fence itself. In the notebook the fences sit at −41.831 and 41.527 while the whiskers stop at −34.637 and 38.737. Points past the whiskers are drawn individually as fliers.

Min–max normalisation

Z-score standardisation

Exam — a reliable question

Needs scaling: k-NN · SVM · PCA · k-means · neural networks · Ridge, Lasso and logistic regression.
Does not: decision trees · random forests · gradient boosting — they split on thresholds, so rescaling a feature does not change the order of its values.
Scaling when unnecessary is harmless. Skipping it when necessary quietly wrecks the model, with no error message.

EncodingExampleUse when
LabelCat, Dog → 0, 1encoding the target class
OrdinalSmall, Medium, Large → 1, 2, 3the categories have a real order

The encoding trap

Ordinal-encoding an unordered feature invents a fake order. The model then believes category 0 is more similar to category 1 than to category 4, which is simply not true.

Discretisation (binning)

Values 1 5 8 12 18 25. Equal-width makes the ranges the same size (1–8, 9–16, 17–25) so counts differ: [1,5,8], [12], [18,25]. Equal-frequency puts the same count in each group so ranges differ: [1,5], [8,12], [18,25].

Selection vs extraction — near-certain exam question

Feature selection keeps a subset of the original columns. To predict whether a student passes: keep study hours, attendance and previous grade; drop favourite colour and student ID.

Feature extraction creates new columns from the originals. Combine weight and height into BMI; combine study hours, attendance and homework into an "academic engagement score".

In selection you keep original columns. In extraction you create new ones. PCA is extraction.

The car dataset the exam asks about
1
Columns: Horsepower · Engine Size · Weight · Length · Width · Height · Fuel Type · Price (the target).
2
Selection. Horsepower and Engine Size correlate at about 0.97 — nearly the same column twice. Drop Engine Size. Seven features become six, and every one still means what it meant, so you can still say "each extra 10 hp adds X to the price".
3
Extraction. Combine Length, Width and Height into one Volume column, or run PCA over all six numeric columns and keep the two components that carry most of the variance. Six features become two — but PC1 is a weighted mixture of weight, power and size, so it has no unit and no plain-English meaning.
4
The sentence that earns the mark: selection chooses among existing columns and preserves their meaning; extraction constructs new columns and usually destroys it.

Framing the problem: choosing features and a target

A short-answer question may hand you a business goal and ask for features and a target. Work in that order — target first, because the target decides whether the task is classification or regression, and that decides every later choice.

Target leakage — the mistake that looks like success

Every feature must be knowable at the moment you need the prediction. For churn, "received a cancellation confirmation email" would predict churn almost perfectly — and be worthless, because it only exists after the customer has already left.

The symptom is a model that performs suspiciously well: 99% accuracy on a hard problem, or a single feature carrying almost all the importance. If you see that, look for a column that encodes the answer. Behavioural features measured before the event are what actually predict it; demographics such as age or gender are usually weak by comparison, which is why "age, gender, location" is a poor answer to a churn question.

Selection methods named in the lectures: the correlation coefficient for numerical features (−1 to +1; positive means they rise together, near zero means no linear relationship) and the chi-square test for categorical features.

Train → tune → freeze the decisions → test once. Proportions vary; 80/20 is common. What matters is the separation itself.

Exam · the analogy to retell

A final exam of twenty questions. You study with practice questions, sit the exam, and get Q3, Q7 and Q15 wrong. You then study exactly those three and sit the same twenty questions again, scoring 100%. But did you learn the subject? No — you learned that exam. That is precisely what happens to a model when test results are used to change it.

Memorisation

  • Remembers specific training examples
  • Performs very well on what it has seen
  • Falls apart on anything new
  • "I remember this exact example."

Learning

  • Discovers general patterns
  • Performs well on new, unseen data
  • That is what generalisation means
  • "I understand the pattern, so I can solve a new one."
Leakage, precisely

Schema checks can come before the split. But anything data-dependent — imputation, scaling, feature selection, outlier thresholds — must be learned inside the training subset. fit on training, transform on everything.

How to tell them apart in practice

High bias → the training error itself is high. The model is too simple.
High variance → training error is low but the gap to validation is large.
That gap has a name: generalisation gap = validation error − training error. And the standard deviation across cross-validation folds is a direct readout of variance.

If underfitting

  • Use a more powerful model
  • Add better features
  • Reduce the regularisation
  • Train longer

If overfitting

  • Get more training data
  • Simplify the model
  • Increase regularisation
  • Tune honestly with cross-validation
  • For trees: prune or limit the depth

Regularised models require scaling. The penalty acts on coefficient size, so a feature measured in kronor gets a very different coefficient from one measured in millions.

Reading the two numbers

Almost every short-answer question on fit gives you a training score and a test score and asks what is happening. The diagnosis is in the gap, not in either number alone — which is why a training accuracy quoted on its own tells you nothing at all.

Exam · "is overfitting likely?" with 68% and 67%

The answer is no — a one-point gap means the model behaves on unseen data almost exactly as it did in training, so nothing was memorised. But stopping there leaves a mark on the table: the scores are both low, so the real problem is underfitting. Say what the numbers do indicate, not only what they rule out.

k-Nearest Neighbours

Lecture 3 · the course's first algorithm
Definition
A supervised algorithm that predicts a new sample by looking at the nearest examples in the training data. k is the number of neighbours used for one prediction.

What it needs

  • Labelled training samples
  • Features on comparable scales — not optional
  • A distance measure, normally Euclidean
  • A value for k

How one prediction works

  • A new sample arrives
  • Measure the distance to every training sample
  • Keep the k smallest
  • Classification: vote. Regression: average.
d(X, Pᵢ) = √[ (x₁ − pᵢ₁)² + (x₂ − pᵢ₂)² ] Only the features enter the distance. The label — the known class, the known price — never does. It is used only after the neighbours have been chosen.

Exam · put a number on why k-NN needs scaling

Suppose the features are Age, Monthly Income and Number of Purchases, and two customers are 20 years apart and 20,000 kr apart. The squared distance adds one term per feature:

age term = 20² = 400   ·   income term = 20,000² = 400,000,000

Income contributes a million times more, so it alone decides who counts as a neighbour — Age and Number of Purchases are present in the model and ignored in practice, however predictive they are. Standardising all three to mean 0 and sd 1 gives each an equal say. One line of arithmetic like this turns "income is bigger so it dominates" into a demonstration, and it is the difference between a safe answer and a full one.

The learning rate breaks everything

Too small → it crawls; it will get there but needs far too many steps. About right → smooth convergence. Too large → each step overshoots the bottom and lands higher up the other side, so the loss grows and the model diverges.

R² is not a percentage of correctness

"R² = 0.85 so the model is 85% accurate" is wrong. It explains 85% of the variance, which says nothing directly about the typical size of an error. R² = 0 means no better than always predicting the mean; R² can go below zero, meaning worse than that baseline. Always pair R² with RMSE or MAE.

MAE or RMSE?

MAE counts every error in proportion to its size and is robust to outliers. RMSE squares first, so big errors dominate. RMSE ≥ MAE always, and a large gap between them means a few big errors are doing the damage — worth a sentence in any report.

How it learns

  1. Start with weights and a bias.
  2. Predict probabilities for the training examples.
  3. Compare with the correct labels — the loss is log loss (cross-entropy).
  4. Use gradient descent to update the weights and reduce the loss.
  5. Repeat until the predictions stop improving.

The log-loss cost is convex, so gradient descent cannot get stuck in a local minimum.

More than two classes

Decision trees

Lecture 5 · the most calculation-heavy exam topic

A tree asks a sequence of yes/no questions about the features. Every internal node is a test, every branch an answer, every leaf a prediction. Training means choosing, at each node, the question that separates the classes best — and "best" is a number you can compute by hand.

Why people like them

  • You can read the rules out loud
  • No feature scaling needed
  • Handles numeric and categorical features
  • Captures non-linear patterns

The catch

  • Overfits badly if grown without limit
  • Unstable — a few changed rows can reshape the whole tree
  • Greedy: it never revisits an earlier split

Impurity: Gini and entropy

Same arithmetic, entropy instead of Gini. Information Gain = Entropy(parent) − weighted Entropy(children). The tree picks the feature and threshold with the largest gain, which is the same as the smallest weighted impurity. Both phrasings appear on exams; they are one calculation.

Regression trees

Same tree, different score. A leaf predicts the mean of the training targets that land in it, and splits are chosen to maximise variance reduction — or equivalently to minimise MSE in the children.

VR = Var(parent) − [ (nL/n)·Var(L) + (nR/n)·Var(R) ] Identical shape to the Gini calculation: parent score, minus the weighted average of the children's scores.

Exam · "one advantage and one disadvantage"

Asked for one of each, give the mechanism with each, not just the word.

Advantage — interpretability. A trained tree is a set of if–then rules you can read aloud: "if income is below 25,000 and employment is under 6 months, predict decline." That matters whenever a decision must be explained to a customer or a regulator. Trees also need no feature scaling and take numeric and categorical features together.

Disadvantage — they overfit, and they are unstable. Grown without limits a tree splits until each leaf holds one row, reaching 100% training accuracy by memorising the data. And because every split is chosen greedily, changing a few training rows can change an early split and reshape the entire tree below it — high variance. Pruning and the depth limits address the first; a random forest addresses both, at the cost of the interpretability you started with.

Pre- vs post-pruning

Pre-pruning stops the tree growing (the parameters above). Post-pruning grows it fully, then cuts branches back if removing them does not hurt validation performance. A fully grown tree on clean data can reach 100% training accuracy — one leaf per row — and that is the warning sign, not the goal.

The two sources of randomness

  • Bagging — each tree gets a bootstrap sample: n rows drawn with replacement, so roughly 63% of the rows appear and some appear twice
  • Feature subsampling — each split considers only √p features (classification) or p/3 (regression), so no single strong feature dominates every tree

Why that helps

  • Individual trees still overfit, but they overfit differently
  • Averaging cancels the uncorrelated errors
  • Variance drops sharply; bias barely changes
  • Out-of-bag samples — the ~37% left out — give a free validation estimate

Why averaging actually works

The claim that combining weak models gives a strong one sounds like something for nothing, so it is worth seeing where the gain comes from. Each tree's prediction carries two kinds of error: a shared part — the bias every tree has because trees make axis-aligned splits — and an individual part that depends on which bootstrap rows and which random features that particular tree happened to get.

Averaging cannot touch the shared part: if every tree is wrong in the same direction, the average is wrong too, so bias barely changes. But the individual parts point in different directions, so they partly cancel. That is why a forest reduces variance and not bias — and why the randomness is deliberately injected rather than avoided. Training forty identical trees on the same rows would give forty identical predictions and no cancellation at all; bagging and feature subsampling exist precisely to make the trees disagree.

It also explains the one case where a forest does not help much: if the single tree is underfitting, every tree shares that bias, and averaging forty underfitting trees gives you an underfitting forest.

Bagging vs boosting

Bagging (random forest) trains trees in parallel on different samples and averages — it attacks variance. Boosting (AdaBoost, gradient boosting) trains trees in sequence, each one focused on the previous one's mistakes — it attacks bias, and is more prone to overfitting noise.

Support vector machines

the widest street between the classes

Many lines separate two classes. An SVM picks the one with the largest margin — the greatest distance to the nearest point of either class. Those nearest points are the support vectors, and they alone define the boundary: move a far-away point and nothing changes.

Margin and the C parameter C controls how much misclassification is tolerated

Hard vs soft margin, and C

Hard margin allows no mistakes — only possible if the classes are perfectly separable, and extremely sensitive to one odd point. Soft margin permits some points inside the margin or on the wrong side. Small C = wide margin, more violations tolerated, more regularisation. Large C = narrow margin, few violations tolerated, risk of overfitting. C is inversely related to regularisation strength.

Exam · "in simple words, what is the margin for?"

Many different lines separate the same two classes. The margin is the empty corridor between the boundary and the nearest training point on each side, and the SVM picks the boundary that makes that corridor as wide as it can.

A wider margin is preferred because it leaves room for error. A boundary pressed up against the training points will misclassify a new point that falls only slightly the wrong way; a wide corridor absorbs that variation, so the model generalises better. In the language of the rest of the course, maximising the margin is a form of regularisation — and C is the dial that trades it away.

Note what the answer must contain to be complete: not only what the margin is, but what a larger one buys you. The question asks for both.

The kernel trick

If no straight line can separate the classes, map the data into a higher-dimensional space where a plane can, without ever computing the coordinates in that space. Common kernels: linear, polynomial, and RBF (radial basis function / Gaussian), the usual default for non-linear problems. In RBF, gamma sets how far a single point's influence reaches — large gamma means very local, wiggly boundaries and overfitting.

SVMs need scaling

The margin is measured as a geometric distance, so a feature in the thousands dominates one in the units. Always standardise before an SVM — same rule as k-NN, same reason.

Definition
An unsupervised technique that finds new axes — the principal components — along which the data varies most, and describes each sample with a few of them instead of all the original features. Why reduce dimensions

  • Fight the curse of dimensionality
  • Remove correlated/redundant features
  • Faster training, less memory
  • Makes 2-D visualisation of many features possible

What it costs

  • Components are mixtures — no longer "size in m²", so interpretability is gone
  • Some variance is always discarded
  • Only captures linear structure
  • Requires standardised data

What a component actually is

A principal component is not a chosen column — it is a direction. PC1 is the line through the data along which the points are most spread out, and each sample's PC1 value is its position along that line. Because the line is at some angle to the original axes, that value is a weighted mixture of every original feature: 0.6 × weight + 0.5 × horsepower + 0.4 × length, say. That is exactly why interpretability is lost — the number has no unit and no name in the world.

PC2 is the most-spread direction among those perpendicular to PC1, and so on. The perpendicularity is what makes the components non-redundant: having captured one direction of variation, PCA refuses to spend the next component re-describing it. The payoff is that a few components can carry most of the information from many correlated columns, which is why PCA is the standard answer to "too many features that say the same thing".

Standardise first, or PCA is meaningless

PCA maximises variance, and variance depends on units. Leave salary in kronor beside age in years and PC1 will simply be salary. Standardise every feature to mean 0, sd 1 first — then fit PCA on the training set only and apply the same transform to the test set.

Exam · explained variance

If PC1 explains 62% and PC2 explains 23%, keeping both retains 85% of the variance and discards 15%. The usual rule is to keep enough components to reach 90–95%, read off a cumulative explained-variance curve (a "scree plot" / elbow).

Choosing k

  • Elbow method — plot inertia against k and take the bend where the improvement flattens

  • Outliers drag centroids
  • Needs scaled features
Exam · supervised vs unsupervised in one line

Classification has labels and learns to reproduce them; clustering has no labels and discovers structure. "Group these customers into segments" is clustering. "Predict which customers will churn" — given past churners — is classification. The presence of a target column decides it.

Exam · what are the weights adjusted for?

A multiple-choice question asks what training a network changes the weights for, and the answer is to reduce the prediction error. Training never adds features, removes layers or duplicates samples — it changes numbers. Each weight is nudged in the direction that lowers the loss, and that is the only thing happening.

This is also the thread that ties the whole course together: linear regression, logistic regression and a neural network are all the same procedure with a different function inside. Define a loss, compute its gradient with respect to each parameter, step against the gradient, repeat. What differs is only the shape of the model and the loss it minimises.

Training is the same loop as everywhere else in this course: forward pass to get predictions, compute the loss, backpropagate the gradients, and update the weights by gradient descent. One pass over the whole training set is an epoch.

model answer

There are in fact five, so name any four and you are safe:

  1. Missing value — Delivery Time is blank for A02. Because Delivered is no, the blank is meaningful: an undelivered order has no delivery time, so I would leave it as NaN rather than impute a fictional one.
  2. Impossible value — Distance is −3.0 km for A03. A distance cannot be negative, so this is invalid rather than merely extreme; treat it as missing or recover the sign.
  3. Wrong data type — Delivery Time for A04 is the word forty. One text entry forces the whole column to be read as text, so convert it to 40.
  4. Inconsistent category — Delivered is Yes for A05 and yes elsewhere. Normalise the case before encoding, or you get two columns for one category.
  5. Duplicate record — A05 appears twice, identical throughout. Drop the exact duplicate.

I would also drop Order ID before training: it is an identifier, unique per row, and a flexible model can memorise it.

Thin answer: "There is missing data, a negative number, a word instead of a number, and a repeated row." Correct observations, but the question says classify. Without the category names — missing value, impossible value, wrong data type, duplicate record — and without what you would do about each, this is half the marks.
17 98% normal and 2% fraudulent transactions — why can accuracy be misleading? Suggest one better measure.
model answer

Accuracy is dominated by the majority class. A model that predicts "normal" for every single transaction scores 98% accuracy while catching no fraud at all — the 98% is simply the base rate, so the model has added nothing. Accuracy cannot distinguish a useful model from that one.

Report recall for the fraud class: of the real fraud cases, how many were caught. Pair it with precision and F1 and show the confusion matrix, since a missed fraud costs money while a false alarm costs a phone call.

Thin answer: "Because the data is imbalanced." True, but it does not explain why that breaks accuracy. The 98%-by-predicting-one-class sentence is the part the examiner is looking for.
18 Salary: 32,000 · 41,000 · 38,000 · 1,500,000 · 36,000. Which value needs investigating, and why?
model answer

1,500,000. Four values sit between 32,000 and 41,000; this one is roughly forty times larger. With Q1 = 36,000 and Q3 = 41,000 the IQR is 5,000, so the upper fence is 41,000 + 7,500 = 48,500 and the value is far outside it. The mean of the five values is 329,400 — above four of the five data points — which is itself a sign that one value is dominating.

It needs investigating, not deleting: it could be a genuine executive salary, a currency mix-up, a unit error, or a typo for 150,000. If it is real, use the median for any imputation, prefer a robust scaler or a log transform over min–max, and report MAE alongside RMSE.

Thin answer: "1,500,000, because it is an outlier, so remove it." The identification is right and the conclusion is wrong. Deleting a genuine data point to tidy the distribution is a modelling error, and saying so is what earns the final mark.

Part E · ordering

19 · the ML workflow

  • D define the prediction problem
  • B prepare and clean the data
  • C train using training data
  • E select or tune using validation data
  • A evaluate on test data

Cleaning before training, and test last and once. Those two constraints fix the whole order.

20 · the k-means loop

  • B choose the number of clusters, k
  • E initialise centroids
  • A assign each point to the closest centroid
  • C recalculate each centroid
  • D repeat until stable

k is fixed before anything runs — the algorithm's main limitation. The loop is only assign + recalculate.

Part F · short answer and reasoning

21 Explain the difference between supervised and unsupervised learning. Give one example of each.
model answer

Supervised learning trains on data that already contains the correct answer — a label column — so the algorithm can compare its prediction with the truth and correct itself. Unsupervised learning has no label column at all; it looks for structure in the features alone, and there is no single correct output to check against.

Example of supervised: predicting whether an email is spam, trained on thousands of emails already marked spam or not spam. Example of unsupervised: grouping shop customers into segments when no segments have been defined, using k-means.

Thin answer: "Supervised has labels, unsupervised does not." That is the distinction but not the difference it makes — that having the answer lets the model measure and reduce its own error. And the question asks for two examples; give both.
22 68% training accuracy and 67% test accuracy. Is overfitting likely? Explain briefly.
model answer

No. Overfitting shows up as a large gap between training and test performance, and here the gap is one percentage point — the model performs on unseen data almost exactly as it did in training, so it has not memorised the training set.

The real concern is the opposite: both scores are low, which points to underfitting — high bias, a model too simple to capture the pattern. More data will not help; a more flexible model or better features will.

Thin answer: "No, because the accuracies are similar." Correct, and it stops one sentence early. Saying what the numbers do indicate turns a safe answer into a complete one.
23 99% training accuracy but 60% test accuracy. What is the problem, and mention two ways to reduce it.
model answer

Overfitting — a 39-point gap. The model has fitted the noise and the individual quirks of the training rows rather than the underlying pattern, so nothing it learned transfers to unseen data.

Two ways to reduce it: (1) simplify the model — limit tree depth with max_depth, raise min_samples_leaf, prune, or reduce the polynomial degree; (2) regularise — add an L1 or L2 penalty, lower C in an SVM, or use dropout in a network. Other acceptable answers: collect more training data, remove noisy or redundant features, or use cross-validation to choose the complexity honestly.

Thin answer: "Overfitting. Use more data and cross-validation." More data genuinely helps. Cross-validation on its own does not reduce overfitting — it detects it and lets you choose a better model. Be precise about which job each technique does.
24 Explain why a validation set should be separate from the final test set.
model answer

The validation set is used many times: every time you compare models, choose k, or tune a depth, you are selecting the option that happens to score best on it. After enough such choices the model is fitted to the validation set, so the validation score is no longer an honest estimate of performance on new data.

The test set is held back and opened once, at the end, precisely so that one untouched estimate survives. If you tune against the test set it becomes a second validation set, the reported score is optimistic, and you have no measurement left of how the model will behave in production.

Thin answer: "So the test set stays unseen." That is the rule restated, not the reason. The reason is that repeated selection fits the model to whichever set you keep scoring against.
25 A k-NN classifier uses Age, Monthly Income and Number of Purchases. Why might scaling matter before calculating distances?
model answer

k-NN decides everything by Euclidean distance, and distance adds the squared difference of each feature. Those three features live on wildly different numeric ranges: ages differ by tens, incomes by tens of thousands.

Take two customers 20 years apart and 20,000 kr apart. The age term contributes 20² = 400 to the squared distance; the income term contributes 20,000² = 400,000,000 — a million times more. Income therefore decides who counts as a neighbour, and Age and Number of Purchases are effectively ignored, however predictive they are. Standardising all three to mean 0 and standard deviation 1 (or min–max to [0, 1]) gives each feature a comparable say.

Thin answer: "Because income is bigger than age, so it dominates." The right instinct. Putting one number on it — 400 against 400 million — turns an assertion into a demonstration, and it takes one line.
26 A company wants to predict whether a customer will cancel a subscription. Suggest three useful features and identify the target variable.
model answer

Target variable: whether the customer cancelled — a binary label, churned (yes/no), making this a classification problem.

Three useful features: (1) number of logins in the last 30 days — falling engagement usually precedes cancellation; (2) months since signing up — churn risk is strongly age-dependent; (3) number of support tickets raised — unresolved frustration predicts leaving. Others that would earn the mark: subscription tier, monthly price, payment failures, whether a discount expired, or use of a key feature.

One caution worth a sentence: a feature must be knowable before the cancellation. "Received a cancellation confirmation email" would predict churn perfectly and be useless — that is target leakage.

Thin answer: "Age, gender, location. Target: churn." Demographics are weak churn predictors, and the answer shows no reasoning about why a feature would carry signal. Behaviour beats demographics here, and saying so is the point.
27 Explain the difference between feature selection and feature extraction, using a dataset about cars.
model answer

Feature selection keeps a subset of the original columns. In a car dataset with Horsepower, Engine Size, Weight, Length, Width, Height and Fuel Type, Horsepower and Engine Size might correlate at 0.97, so I drop Engine Size. The surviving columns still mean exactly what they meant, so the model stays interpretable.

Feature extraction builds new columns out of the old ones. I could combine Length, Width and Height into a single Volume column, or run PCA and keep two components that capture most of the variance in all seven columns. The new features are mixtures: a component is no longer "weight in kg", so interpretability is lost even though the information is compressed.

In short: selection chooses, extraction constructs. Selection preserves meaning; extraction usually destroys it in exchange for fewer dimensions.

Thin answer: "Selection picks features, extraction extracts them." This restates the words without distinguishing them. The discriminating sentence is whether the output columns are original or newly constructed, and a car example makes it concrete.
28 A model predicts a patient does not have a disease, but the patient does. Is this a false positive or a false negative? Why can this error be serious?
model answer

A false negative: the model predicted negative (no disease) while the truth was positive. In the confusion matrix it is the FN cell, and it is the error that recall — TP ÷ (TP + FN) — measures the absence of.

It is serious because the patient is told they are healthy and sent home, so the disease goes untreated and may progress to a stage where treatment no longer works. A false positive, by contrast, leads to an unnecessary follow-up test — stressful and expensive, but recoverable. Because the two errors are not comparable in cost, a medical screening model is tuned for high recall even at the price of more false alarms, and accuracy is the wrong headline metric.

Thin answer: "False negative, because the model missed the disease." The classification is right and the "why serious" half of the question is unanswered. Name the consequence, and contrast it with the cost of the opposite error.
29 Explain one advantage and one disadvantage of decision trees.
model answer

Advantage — interpretability. A trained tree is a set of if–then rules you can read out loud: "if income is below 25,000 and employment is under 6 months, predict decline." That matters when a decision must be explained to a customer or a regulator. They also need no feature scaling and handle numeric and categorical features together.

Disadvantage — they overfit, and they are unstable. Grown without limits a tree keeps splitting until each leaf holds a single row, reaching 100% training accuracy while learning the noise. They are also high-variance: changing a few training rows can reshape the whole tree, because each split is chosen greedily and every later split depends on it. Pruning, max_depth and min_samples_leaf control the first problem; a random forest addresses both, at the cost of the interpretability you started with.

Thin answer: "Advantage: easy to understand. Disadvantage: can overfit." Both correct, both unexplained. One clause of mechanism after each — why readable, why it overfits — is the difference between naming and understanding.
30 An SVM separates two classes with a decision boundary. In simple words, what is the purpose of the margin, and why is a larger margin usually preferred?
model answer

Many different lines can separate the same two classes. The margin is the empty corridor between the boundary and the closest training point of each class, and the SVM chooses the boundary that makes that corridor as wide as possible. The points that touch the corridor are the support vectors, and they alone determine the boundary — moving a distant point changes nothing.

A larger margin is preferred because it leaves more room for error. A boundary squeezed right up against the training points will misclassify a new point that falls only slightly on the wrong side; a wide corridor tolerates that variation, so the model generalises better. In bias–variance terms, maximising the margin is a form of regularisation — which is exactly what the parameter C trades away when you increase it.

Thin answer: "The margin is the distance to the nearest points, and bigger is better." It defines the margin without saying what it buys. The reason is room for unseen points to vary — generalisation — and the question explicitly asks why.
The pattern across all ten

Every thin answer above fails the same way: it stops after the identification. The examiner has already given you the identification in the question; the marks are in the mechanism (why this happens) and the consequence (what it costs you). If an answer of yours is one sentence long, it is probably missing one of those two.
